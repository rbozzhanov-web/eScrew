AIMS eCrew Parser Architecture

Complete technical specification for building a production-grade parser integrating Air Astana's closed AIMS eCrew system with your application infrastructure.

System Architecture

Interaction Schema

The parser operates as middleware between your application and AIMS eCrew, handling all session management, data extraction, and error recovery transparently.

┌─────────────────────────────────────────────────────────────┐ │ Your Application │ │ (FastAPI/Django/Node.js + Database) │ └────────────────────┬────────────────────────────────────────┘ │ REST API (JSON) │ GET /api/schedule │ GET /api/crew/{id} │ POST /api/sync ▼ ┌─────────────────────────────────────────────────────────────┐ │ AIMS Parser Middleware (FastAPI + Docker) │ ├─────────────────────────────────────────────────────────────┤ │ • Session Manager & Auth Layer │ │ • HTTP Client (requests/httpx) │ │ • Parser Engine (BeautifulSoup4 + lxml) │ │ • Cache & Queue (Redis) │ └────────────────────┬────────────────────────────────────────┘ │ HTTPS (Session cookies + CSRF) ▼ ┌────────────────────────────────┐ │ AIMS eCrew (Air Astana) │ │ https://aims.airastana.com/ │ └────────────────────────────────┘

Parsing Algorithm

Phase 1: Authentication

  1. Load login page → Extract CSRF token from <meta name="csrf-token"> or hidden input
  2. POST credentials → Include CSRF token in X-CSRF-Token header
  3. Verify success → Check 200 OK + session cookies/JWT token
  4. Cache session → Store in Redis with 25-minute TTL (below AIMS session timeout)

CSRF Token Rotation: Some implementations rotate CSRF tokens on each request. Extract from response headers or body; update before each POST operation.

Phase 2: Schedule Fetch

  1. POST request with date range → POST /api/schedule?start_date=...&end_date=...
  2. Handle rate limiting (429) → Respect Retry-After header, exponential backoff
  3. Check response format → JSON API or HTML (requires browser automation)
  4. Parse data → Extract via XPath/CSS selectors or Selenium + render

Implementation

Authentication Module

import requests
from bs4 import BeautifulSoup
import redis
import logging

logger = logging.getLogger(__name__)
redis_client = redis.Redis(host='localhost', port=6379)

class AImsAuthenticator:
    """Authenticate against AIMS eCrew with CSRF protection"""

    BASE_URL = "https://aims.airastana.com"
    LOGIN_URL = f"{BASE_URL}/api/auth/login"

    def __init__(self, username: str, password: str):
        self.username = username
        self.password = password
        self.session = requests.Session()

    def get_csrf_token(self) -> str:
        """Extract CSRF token from login page"""
        response = self.session.get(f"{self.BASE_URL}/login", timeout=10)
        soup = BeautifulSoup(response.text, 'html.parser')

        csrf_meta = soup.find('meta', {'name': 'csrf-token'})
        if csrf_meta:
            return csrf_meta.get('content')

        csrf_input = soup.find('input', {'name': '_csrf'})
        return csrf_input.get('value') if csrf_input else None

    def authenticate(self) -> tuple[bool, str]:
        """Perform authentication with automatic retry on CSRF mismatch"""
        csrf_token = self.get_csrf_token()

        response = self.session.post(
            self.LOGIN_URL,
            json={"username": self.username, "password": self.password},
            headers={'X-CSRF-Token': csrf_token},
            timeout=15
        )

        if response.status_code == 401:
            return False, "Invalid credentials"
        if response.status_code == 200:
            redis_client.setex(f"aims:{self.username}", 1500,
                            self.session.cookies.get_dict())
            return True, "OK"

        return False, f"HTTP {response.status_code}"

Fetcher Module

class ScheduleFetcher:
    """Fetch and parse AIMS schedule data"""

    def fetch_schedule(self, start_date: str, end_date: str,
                    max_retries=3) -> dict:

        for attempt in range(max_retries):
            response = self.session.get(
                f"{self.BASE_URL}/api/schedule",
                params={"start_date": start_date, "end_date": end_date},
                timeout=30
            )

            # Rate limit: respect Retry-After
            if response.status_code == 429:
                wait = int(response.headers.get('Retry-After', 60))
                if attempt < max_retries - 1:
                    time.sleep(wait)
                    continue

            if response.status_code == 401:
                return {'error': 'Unauthorized', 'need_reauth': True}

            if response.status_code == 200:
                try:
                    return {'data': response.json(), 'format': 'json'}
                except:
                    return {'data': response.text, 'format': 'html'}

        return {'error': 'Max retries exceeded'}

Logging Without Data Leaks

import logging
import re

class SanitizedFormatter(logging.Formatter):
    PATTERNS = [
        (r'password["\']?\s*[:=]\s*["\']([^"\']+)["\']',
         r'password: ***REDACTED***'),
        (r'Authorization.*Bearer\s+(\S+)',
         r'Authorization: Bearer ***TOKEN***'),
    ]

    def format(self, record):
        msg = super().format(record)
        for pattern, replacement in self.PATTERNS:
            msg = re.sub(pattern, replacement, msg)
        return msg

Log to structured sinks: Send all production logs to CloudWatch / Datadog with field-level encryption for sensitive fields. Never write passwords to application logs.

Risk Matrix & Mitigation

Risk Probability Impact Mitigation
HTML Structure Change High Critical Use XPath + CSS selectors with fallbacks; weekly monitoring; automated alerts on parser errors
CAPTCHA Introduction Medium High 2Captcha API; reduce request frequency; Cloudflare bypass techniques
IP Blocking Medium High Proxy rotation (Bright Data); rate limiting ≤3 req/min; VPN/SSH tunnel
Session Expiry High Medium Auto re-auth on 401; Redis cache with TTL < AIMS timeout
Credential Compromise Low* Critical Vault storage; rotate quarterly; MFA on source accounts; audit logs

* Low only with security practices enforced

Monitoring Strategy

Alert Conditions

  • 5+ 404 errors in 10 min: AIMS structure changed → trigger oncall review
  • 3+ consecutive 429 responses: Rate limit detected → increase backoff delay
  • All requests return 403: IP likely blocked → activate proxy rotation
  • P99 latency > 30s: Network issue or slow response → check AIMS status page
