# Import a saved AIMS Web Archive without touching Files

Normally, importing from AIMS means: Safari → Share → Options → Web Archive →
**Save to Files** → switch to eScrew → pick that file. This Shortcut is a
local bridge that skips the Files trip: it grabs the Web Archive straight
from the Share Sheet, puts it on the device-only clipboard, and eScrew
imports it with one deliberate tap. No file is saved to Files, and no byte
is uploaded anywhere.

This uses the same clipboard-bridge technique as the companion
[OFP Viewer app's Shortcut](https://github.com/rbozzhanov-web/Iphone-OFP-viewer/blob/main/SHORTCUT_IMPORT.md).
It is **not** related to eScrew's older Shortcut-based capture (removed a
while back), which ran live inside the AIMS Safari tab under a hard
execution time limit and broke often as a result. This one only ever
touches a Web Archive that's already been generated by Safari — nothing
runs against the live page.

## Why this extracts just the schedule, not the whole archive

A real AIMS Web Archive runs 9–10MB, but only about 180KB of that is the
actual `CrewSchedule` page eScrew's importer reads — the rest is AIMS's own
JS bundle, fonts and CSS, snapshotted along with the page by Safari's Web
Archive format for no reason that matters here. Sending the whole thing
across the clipboard turned out to be unreliable in practice: two separately
saved archives (one from the in-app popup, one from real Safari) were both
confirmed byte-for-byte valid and importable when checked directly, yet both
still failed with `Unsupported AIMS file` when actually pasted through the
Shortcut. That points at the transport, not the content — likely the
~9.5MB Base64 Encode either exceeding a Share Sheet extension's execution
budget, or exceeding a practical size ceiling on iOS's shared clipboard —
and both of those get dramatically less likely to bite once the payload
is ~50x smaller. Verified independently (outside Shortcuts, replaying the
exact bytes through eScrew's real decode logic) that extracting just the
`CrewSchedule` HTML fragment and sending only that parses correctly — the
receiving side needs no changes at all, since `parseRosterData` already
accepts bare HTML bytes, not just a full Web Archive.

The one part that's genuinely untested is whether Shortcuts' dictionary
actions can actually read a *binary* `.webarchive` plist on your device —
that's real property-list parsing, not JSON, and needs to be tried by hand
below.

## Make the Shortcut once

In **Shortcuts**, create a shortcut named **Import to eScrew**.

1. Open the shortcut's details. Enable **Show in Share Sheet**.
2. Under *Share Sheet Types*, select whichever types include Web Archives on
   your iOS version — usually **Files**, sometimes listed alongside **Web
   Pages**. If Safari's Web Archive share option doesn't offer this Shortcut
   as a destination, try widening the type selection.
3. Add **Get Dictionary from Input**. Feed it the *Shortcut Input*. This
   parses the Web Archive's underlying property list — Apple's Property
   List and JSON are both dictionary formats this action is documented to
   read, but confirm on your device that it doesn't error out here; if it
   does, that's the sign this approach doesn't work on your iOS version and
   you should fall back to the "send everything" recipe at the bottom.
4. Add **Get Dictionary Value**. *Get*: **Value**. *Key*: `WebSubframeArchives`.
   Input: the dictionary from step 3. This returns a list.
5. Add **Get Item from List**. *Get*: **First Item**. Input: the list from
   step 4. This returns a dictionary — the one and only subframe archive,
   which is where AIMS's Crew Schedule content actually lives (the outer
   Web Archive wraps the Dashboard page instead; the schedule itself is a
   sub-frame inside it).
6. Add **Get Dictionary Value** again. *Key*: `WebMainResource`. Input: the
   dictionary from step 5.
7. Add **Get Dictionary Value** a third time. *Key*: `WebResourceData`.
   Input: the dictionary from step 6. This is the actual raw HTML — the
   ~180KB fragment, not the 9–10MB archive.
8. Add **Base64 Encode**. Feed it the **Data from step 7** (not the original
   Shortcut Input this time). Set *Line Breaks* to **None**.
9. Add a **Text** action. Its text must be exactly:
   `ESCREW-WEBARCHIVE-v1:` followed immediately by the magic variable from
   the Base64 action — no spaces and no new line.
10. Add **Copy to Clipboard**. Feed it the Text output and enable **Local
    Only**.
11. Add **Show Notification** with: `Open eScrew — a Paste from Shortcut
    banner is waiting.`
12. *(Optional, experimental)* Add **Open URL** after the notification,
    pointing at eScrew's URL (e.g.
    `https://rbozzhanov-web.github.io/eScrew/`). Likely opens a plain Safari
    tab rather than your installed Home Screen icon (separate storage
    contexts on iOS) — try it, drop it if it's more confusing than helpful.

### If step 3 doesn't work — fallback recipe

Some iOS versions' dictionary actions may not parse a binary Web Archive
plist cleanly. If step 3 errors, or later steps come back empty, replace
steps 3–7 with a single **Base64 Encode** fed directly by the *Shortcut
Input* (the whole archive) instead — this is the original, larger-payload
version, and it's what to fall back to if the trimmed version doesn't work
on your device. It's the same one more likely to be unreliable given
everything above, but it's a known-working starting point to debug from.

## Use it

1. Open Crew Schedule in AIMS and wait for it to finish loading.
2. **Share → Options → Web Archive**, then tap **Import to eScrew** instead
   of Save to Files.
3. eScrew notices when it comes back to the foreground and shows a small
   **Paste from Shortcut?** banner on its own — tap it and allow paste when
   iOS asks. If the banner doesn't appear (or was dismissed, or timed out),
   tap the **AIMS** button, then **Paste Web Archive from Shortcut**, same
   result either way.

See `src/import/pickRoster.ts` (`pasteRosterFromClipboard`) for the
receiving side — unchanged by any of this, since it already accepts bare
HTML bytes as readily as a full Web Archive. The normal file picker
(**Import Web Archive or PDF**) remains available and unaffected either way.
